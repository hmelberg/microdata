Microdata

An emulator of microdata.no — write and run microdata code.

What is this?

An emulator of microdata.no. You write microdata commands, they are translated to Python and run in the browser against synthetic register data. The goal is that a script that works here also works there.

The commands

The microdata language is deliberately small. Each command does one thing, and the order is the one you'd write on paper: fetch data, build variables, summarize. The list below is limited to commands that are actually implemented in m2py.py.

collapse statistics: mean · min · max · median · sum · count · sd · semean · sebinomial · percent · iqr · gini. collapse (first) and collapse (last) do not exist — neither here nor on microdata.no; use an aggregated statistic instead.

Disclosure control

The emulator censors output the same way microdata.no does, because a script that produces numbers here and gets rejected there isn't much help. The control is on by default in the app. The thresholds below are taken directly from the constants in m2py.py (lines 267–272), not from memory:

RuleThresholdEffect when triggered
Min. population1000 unitskeep if, drop if and sample are rejected if the result would have fewer units. The dataset is left unchanged.
Min. change10 unitsgenerate, replace and recode are rejected if the change affects 1–9 units (or all but 1–9). Exception: all or none.
Min. population for descriptive stats10 unitssummarize, correlate, ci, anova, normaltest are blocked below the threshold — per group as well. Exception: plain count/sum.
Small cells in tablesfrequency <5 in >50% of cellstabulate (and the panel variants) are blocked if more than half the cells have fewer than 5 units.
Winsorizing1st and 99th percentileNumeric variables are clipped at the 1st/99th percentile before mean and standard deviation are shown in summarize, and before histogram/scatter/boxplot are plotted. Median and quartiles are unaffected. Regression and collapse use raw data.
Percentile rounding3 significant digitsMedian and percentiles in summarize are rounded — e.g. 47,238 → 47,200, 2.7183 → 2.72.
Pseudonym validationvariable names ending in _FNRCan only be used as a key in collapse(by) or merge(on) — rejected in generate, replace and comparisons.
Type checkalphanumeric variableRejected for numeric operations (min, max, mean, sum, median). Use frequency/tabulate instead.
Missing comparisoncomparison with .== ./!= . is rejected outright (Stata syntax is not valid in microdata.no). Assignment (= .) is OK. Use sysmiss(x) to test whether a value is missing.

Turning it off

Add the directive at the top of the script:

// m2py: disclosure-control=off

The directive is an ordinary comment, so microdata.no ignores it. The same script can run in both places.

What you lose: with the control off, the numbers are no longer comparable to what you'd get in production. Turn it off to understand the data, not to report it.

Differences from microdata.no

The emulator isn't perfect. These are the known differences — not a disclaimer, but a list.

AreaHereOn microdata.no
Data connection (require) require source as alias is a syntax-faithful copy that logs a message and otherwise does nothing — whichever source you write makes no difference to what you can later import (the code itself is commented "No-op against actual SSB" in m2py.py). require actually connects to an approved register source. Access requires an application and approval, and only the variables the source actually contains are available.
The data itself All values come from a seeded synthetic generator (MockDataEngine/mockdata_core.py). Distributions are approximately realistic, but the numbers are made up and bear no relation to real registers. Real, de-identified register data, subject to the same disclosure control the emulator imitates.
Other modes (Python, R, DuckDB, Brython, Statx, jamovi) Six extra runtime environments available from the same editor, as an addition beyond the microdata language itself — useful for further analysis or comparing approaches. These engines are not part of the service being emulated here. They were added by this hobby project, not a claim that microdata.no offers them.
Script storage and sharing Scripts are stored as local files, in a GitHub repo you connect yourself, or as a compressed link in the URL. Projects and notebooks are stored and shared inside the service itself (server-side) — not via GitHub or URL compression.

If you find a difference that isn't listed here, it's worth reporting.

py2m and r2m

If you'd rather write Python or R, you can have it translated into microdata commands. The Translate button (the arrow icon) does the translation — the result appears in the output field. To run the translated code, copy it into the editor and switch to microdata mode. The translation isn't complete; it covers the patterns that have a natural microdata form, and anything it can't translate is printed as a visible comment or an // UNTRANSLATED line — never silently dropped.

FromToCovers
Python (pandas) microdata Column operations, row filtering, group aggregation, frequency/cross tables, descriptive statistics, sampling, and OLS/logit/probit/poisson regression with prediction — AST-based, tested by 94 tests in py2m/tests/.
R (tidyverse) microdata dplyr chains (filter/mutate/select/rename/group_by+summarise), base-R and package models (lm, glm, lme4::lmer, plm::plm, survival::coxph etc.), plus recode/case_when/case_match — tested by 184 tests in r2m/test_r2m.R.

What the translator does not cover: control flow (loops over anything but literals, apply/lapply/sapply), positional row selection, sorting, deduplication, data I/O (read_csv/read.csv), and result inspection (head(), summary(model)). These produce either a clear // UNTRANSLATED line (py2m) or a // comment (r2m) — never a silently wrong row.

Python in py 
df = df[df["alder"] > 25]
df.groupby("kjonn")["lonn"].mean()
microdata out 
keep if alder > 25
tabulate kjonn, summarize(lonn)
R in r 
df <- df %>% filter(alder > 25)
df %>% group_by(kjonn) %>% summarise(snitt = mean(lonn))
microdata out 
keep if alder > 25
collapse (mean) lonn -> snitt, by(kjonn)

Editor

Click a line number to set a red breakpoint. During Run step by step, execution pauses at the breakpoint and waits for you to press continue. The full list of keyboard shortcuts is in the reference.

Tab autocomplete

Press Tab in the editor for context-aware suggestions: commands, variable names, DataFrame methods and more. After / (e.g. import db/), microdata variables from the catalogue are suggested. On an empty line, commands are suggested.

Tip: Press Tab in the middle of a word to filter the list by what you've already typed. See full reference for all context rules.

Dataset panel (right sidebar)

The sidebar on the right shows all datasets loaded in the current run.

  • Number of variables and rows per dataset
  • Variable list with type icon: ABC text, 123 numeric, shield icon for pseudonymised ID

The sidebar updates automatically after each run and after each block in Run step by step mode.

Save, share and fetch scripts

All the options below are in the hamburger menu at the top left. They run entirely in your browser — we never store your scripts on a server.

Download code / Load file

Download code downloads the script as a .txt file to your machine. Load file (local) opens such a file again. This is purely local file handling.

Share (copy link)

Creates a link that contains the entire script, compressed into the address itself (after #). The link is copied to the clipboard — send it by email, Slack, or paste it wherever you like. Whoever opens the link gets the script directly into the editor.

  • Nothing is stored with us, and the recipient does not need to log in.
  • The link is a frozen snapshot — if you change the script afterwards, you must share a new link.
  • Suitable for scripts up to a few thousand characters. If the script is too large for a URL, you'll be notified — use "Download code" (file) or GitHub instead.
Script in the editor url 
print(sum(range(1, 101)))
Result — what the "Share" button produces 
{"v":1,"name":"","lang":"python","script":"print(sum(range(1, 101)))"}

The part before # is your own address (shown as a placeholder above); everything from #s= on is real — the script, wrapped in JSON, gzip-compressed and base64url-encoded straight into the link itself.

Open from URL

Paste a direct link to a text file, and the content is fetched into the editor. The most recent URLs you've used are remembered locally for quick reopening.

  • Works with GitHub "raw" links, GitHub gist (raw) and Dropbox.
  • Regular share links (e.g. a Google Drive or GitHub page) do not work — you must use the raw file link. If you get an error message, it's almost always because the source doesn't allow direct fetching (CORS).
  • The file extension controls the mode: .py → Python, .r → R, otherwise the default mode.

GitHub (advanced)

Lets you save and fetch scripts directly in your own GitHub repo — with version history and the ability to collaborate. Everything is under the GitHub submenu in the hamburger menu.

1. Settings (one-time). Fill in a personal access token (PAT), repo (owner/name) and branch. Press Test connection to confirm, and Save settings. The information is remembered locally in the browser. You do not need to specify any file path here — you're connecting to the repo, not a single file.

Multiple profiles. If you have several repos or accounts (e.g. work and personal), you can save them as separate profiles and switch between them in the dropdown at the top of the dialog ("New" to add, "Delete" to remove). The selected profile controls Open/Save. With Show and Copy you can view or copy the token — useful when setting up the same profile on another machine.

How to create a token: GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token. Give it access to only the relevant repo, and set Repository permissions → Contents → Read and write. Copy the token (shown only once) and paste it into the app. Feel free to set an expiry date; you can revoke the token at any time on the same page.

2. Daily use. Once the connection is set up:

  • Open file… shows a file picker with all the files in the repo. Filter in the search field and click a file to fetch it into the editor.
  • Save writes to the file you last opened or saved (the current file, marked with a cloud symbol ☁ next to the script name). If you don't have a current file yet, it behaves like "Save as". If you open a new or different script (New, local file, example, link or URL), the cloud symbol is disconnected so you don't accidentally overwrite the wrong file.
  • Save as… lets you type a new file path (existing folders are suggested). The .txt extension is added automatically if you don't type one.
  • Refetch fetches the current file again from GitHub (reads — does not save). Unsaved local changes are lost, so you'll be asked to confirm.
  • One token, many files: the token applies to the whole repo — you don't need a token per file.
  • Public vs. private is controlled via the repo's own setting on GitHub — not in the app.
  • Sharing: if the script is in a public repo, you just share the raw file link; the recipient uses "Open from URL".
  • The token is a secret and is stored in plain text in your browser. Use a shared machine with care, and revoke the token if you lose access to the machine.

Recently used

A small down-arrow icon (▾) next to the filename shows the most recent GitHub and URL scripts you've opened, so you can fetch them again with one click without typing the whole address. (Local files cannot be reopened by the browser.)

Where is everything stored — and does it work on multiple machines?

It's useful to distinguish the file from the machine:

  • Scripts stored in GitHub live in the cloud and are accessible from anywhere. On a new machine you just paste in the same token once (or nothing if the repo is public — then you use "Open from URL").
  • Share links carry the script within themselves and work on any machine.
  • What is tied to one machine is only local things in the browser: the list of "recent URLs" and the pasted-in GitHub token. Your actual scripts in GitHub are not locked to the machine.

Run step by step — a step-by-step walkthrough

Run step by step runs the script one block at a time and reads the comments aloud using speech. Comment lines — those starting with # or //, depending on which comment character the mode uses — are read aloud; the code lines are executed without commentary. Useful for presentations and teaching.

Blocks

A block is a group of consecutive lines with no blank lines between them. One or more blank lines separate blocks.

# This comment is read ALOUD before the code runs
df["alder"] = 2024 - df["fodselsar"]

# This is the next block
df.groupby("kjonn")["lonn"].mean()
# This comment is read after the result is shown

What Run step by step actually makes of that script — two blocks, one leading and one trailing comment. Widgets in Run step by step

Widgets are interactive cards shown while the script runs step by step. They are inserted as special comment lines and are available in all modes.

Syntax

#widget NAME { ...json... }

The comment character follows the mode: # in most modes, // in modes that use it as the comment character — both are interpreted the same way.

Block syntax for longer content

For HTML, SVG and markdown with multiple lines, you can use block syntax instead of JSON:

//start_widget:html(title="Example", speak="Here you see HTML content.")
<div style="text-align:center">
  <h2>Hello from HTML</h2>
  <p>Multiple lines without escaping.</p>
</div>
//end_widget

AI assistant

An experimental side panel with an AI assistant that can answer questions about syntax, suggest variables, and generate or revise scripts. Opened with the star icon at the top right or Ctrl+I.

Requires an API key. Click the gear icon in the AI panel to set it up. The key is stored only locally in the browser (localStorage).

What the assistant can do

The assistant classifies the question and answers in one of three ways:

  • Question — explains commands, syntax and usage ("What does this function do?")
  • Variable search — finds relevant variables in the data catalogue ("What variables exist for education?")
  • Script generation — creates a complete script from a natural-language question ("Show summary statistics for income and gender")

Revising an existing script

To let the assistant modify the script in the editor, you must check "Include script from editor (revise)" right above the text field before sending. This uses the content of the editor as a starting point, and the request is interpreted as a revision — for example "Add log income" or "Filter on age over 25".

Without this checkbox checked, a new script is created from scratch, even if the editor has content.

Buttons on generated scripts

When the assistant returns a script, three buttons are shown under the code block:

  • 📋 Copy — copies the script to the clipboard
  • ⬇ Replace script — replaces everything in the editor with the generated script
  • + Add — appends the script to the bottom of the editor

Validation warnings

Generated scripts are run through static validation before being shown. If there are unknown variables, unknown commands or parsing errors, these are shown as clickable chips under the script. Click a chip to compose a follow-up message asking the assistant to fix that specific error.

Time usage

Questions and variable searches usually respond in under 5 seconds. Script generation and revision can take 20–60 seconds, up to ~3 minutes for complicated requests — you'll see a "Thinking… Ns" counter while the job runs in the background.

Other controls

  • Gear icon — change API key and other settings
  • Trash icon — clear the conversation (does not delete anything on the server)
  • × — close the panel
  • Enter sends, Shift+Enter inserts a new line

Privacy

What is sent to the API is only your question text, and — if checked — the content of the script editor. Data files, run results, output and widget content are not sent. Norwegian or English language is guessed automatically from the question.

Experimental. The AI assistant can be wrong, suggest variables that don't exist, or generate scripts that don't run. Always check the result before use.

Getting a key in Microdata

Paste your own Anthropic key (created at console.anthropic.com) under the gear icon in the AI panel. The key is stored only locally in the browser (localStorage) and is sent as an X-Anthropic-Key header directly to Anthropic on every request — there is no server in between here.

Hybrid scripts

You can mix microdata, Python and R in the same script by using mode-switch lines.

Switch lines

LineEffect
## microdata / #micro / // microdataSwitch to microdata mode
## python / #pySwitch to Python mode
## r / #rSwitch to R mode

Sharing data between languages: # use

Microdata and Python blocks share datasets automatically, and microdata datasets are copied to R blocks automatically. Between Python↔R and DuckDB↔others, fetch a dataset explicitly with a use line at the top of the block:

#py
df["ny"] = df["x"] * 2

#r
# use df
summary(df$ny)

Without from, the dataset is fetched from the nearest earlier block in a different language; specify # use df from python|r|duckdb when needed (required when the source is a previous run). Copy semantics: the block gets a snapshot — changes do not propagate back to the source engine.

Example: microdata + Python

## microdata
require no.ssb.fdb:52 as db
create-dataset df
import db/BEFOLKNING_FOEDSELS_AAR_MND as faarmnd
import db/INNTEKT_WLONN 2022-01-01 as inntekt
generate alder = 2022 - int(faarmnd / 100)
keep if inrange(alder, 25, 67)
keep if inntekt > 0

## python
import matplotlib.pyplot as plt
df.plot.scatter(x="alder", y="inntekt", alpha=0.3, s=8)
plt.tight_layout()
show(plt.gcf())

Example: microdata + R

Tab autocomplete — full reference

Press Tab in the editor for context-aware suggestions. The rules are the same in every mode:

ContextSuggestion
After / (e.g. import db/) Catalogue variables, in modes with a connected source catalogue
Empty start of line Commands or keywords for the active mode — e.g. Python built-in functions, R base R and tidyverse functions
Only whitespace to the left Inserts 2 extra spaces (indentation)
Python df. Columns in df (if known), otherwise pandas DataFrame methods
R df$ Columns in df
Python import Common data science libraries (pandas, numpy, sklearn ...)
R library( Common R packages; the package name is inserted with parentheses
No match otherwise All known column names from loaded datasets
